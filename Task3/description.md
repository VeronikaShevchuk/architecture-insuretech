# Выявленные проблемы и риски

## Синхронная связность и каскадные сбои
|Проблема|Риск|
|----|----|
|ins-product-aggregator синхронно вызывает 5+ страховых компаний|При падении одного внешнего API тормозятся все|
|core-app синхронно ждёт ответа от aggregator каждые 15 минут| При зависании aggregator core-app тоже зависает|
|ins-comp-settlement синхронно вызывает два сервиса раз в сутки|Ночной batch может упасть из-за недоступности одного API|

## Масштабирование при подключении 5 новых страховых компаний
|Метрика|Сейчас|После подключения 5 новых компаний|Риск|
|----|----|----|----|
|Количество внешних API|5|10|Удвоение времени ответа aggregator|
|RPS на aggregator|Низкий|Вырастет пропорционально|Тайм-ауты и ошибки|
|Нагрузка на core-app|1 запрос/15 мин|То же|Не изменится, но зависимость остаётся|
|Нагрузка на ins-comp-settlement|2 запроса/сутки|То же|Критично только при сбоях|

## Проблемы с данными
|Проблема|Последствия|
|----|----|
|Локальные реплики в core-app и ins-comp-settlement|Данные могут быть устаревшими (до 15 мин и до суток)|
|Нет гарантии доставки|При сбое aggregator данные не обновляются|
|Нет транзакционности|При ошибке часть данных может быть потеряна|
|Разные интервалы обновления|Несогласованность данных между сервисами|

## Операционные риски
|Риск|Описание|
|----|----|
|N+1 проблема|1 запрос → 10 внешних вызовов → легко превысить лимиты|
|Нет изоляции сбоев|Падение одного внешнего API валит всё|
|Нет кэширования ошибок|При ошибке повторные запросы продолжаются|
|Нет мониторинга задержек|Трудно определить источник проблем|

## Ключевые изменения в архитектуре
    1. Добавлен Kafka (Yandex Message Queue)
    Центральная шина событий для асинхронного взаимодействия

    Три топика: products, products.settlement, policies

    2. Реализован паттерн Transactional Outbox
    В ins-product-aggregator и core-app

    Гарантирует exactly-once delivery

    События публикуются атомарно с изменениями в БД

    3. Асинхронные взаимодействия
    ins-product-aggregator публикует события → Kafka

    core-app подписывается на products (заменяет синхронные запросы)

    ins-comp-settlement подписывается на products.settlement и policies

    4. Circuit Breaker для внешних API
    Защита от каскадных сбоев

    Изоляция проблемных страховых компаний

    Тайм-ауты и повторные попытки

    5. Поддержка 10+ страховых компаний
    Горизонтальное масштабирование без изменения кода

    Асинхронные параллельные вызовы
